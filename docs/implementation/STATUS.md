# وضعیت اجرای Cutora

آخرین به‌روزرسانی بسته تحویل: ۲۹ اکتبر ۲۰۲۶.

## خلاصه واقعی

**فقط مستندات، پرامپت شروع و سه موکاپ مفهومی تهیه شده‌اند. هیچ کد محصول یا installer در این بسته ساخته نشده است.**

| مورد | وضعیت | شاهد |
|---|---|---|
| انتقال اسناد بررسی به ساختار ریپو | آماده در بسته تحویل | docs/planning و docs/reference |
| موکاپ‌ها و پرامپت‌های تصویر | آماده در بسته تحویل | سه PNG و PROMPTS در docs/design/mockups |
| منابع Notion برای مطالعه آفلاین | آماده در بسته تحویل | صفحه اصلی و پنج زیرصفحه در docs/reference/notion |
| قرارداد مدیریت رسانه/هارد | مستند شده | docs/specs/MEDIA_WORKFLOWS.md |
| دستور ادامه روی کیس | مستند شده | START.md، AGENTS.md و PLAN.md |
| پیاده‌سازی، import، دسته‌بندی و انتقال هارد | **شروع نشده** | هیچ acceptance محصول پاس نشده |
| بکاپ و restore محصول | **آزمون نشده** | MWها همگی Not Run |
| Resolve assistant | **آزمون نشده** | R0 تا R3 اجرا نشده |
| build و نصب‌کننده | **وجود ندارد** | M0 شروع نشده |
| انتشار بسته مستندات در GitHub | تاریخچه Git را کنترل کن | آخرین commit روی main مرجع نتیجه انتشار است |

## اقدام بعدی دقیق

پس از دستور شروع کاربر روی کیس، **M0 در PLAN.md** را اجرا کن: وضعیت Git/کد و OS/hardware/space همان کیس را بررسی کن، سپس کوچک‌ترین مسیر Electron + SQLite worker + FFmpeg + installer آزمایشی را ثابت کن. مسیرها و نسخه‌ها را از سیستم جدید تعیین کن؛ اعداد سیستم مبدأ را مبنا نگیر.

اگر پیش از شروع کد واقعی در repo موجود بود، این وضعیت تاریخی را به‌روزرسانی و از روی کد/تست واقعی ادامه بده؛ آن را overwrite نکن.

## قالب به‌روزرسانی توسط نشست بعدی

```text
تاریخ و commit:
milestone جاری:
قابلیت واقعی تحویل‌شده:
نسخه‌های ابزار/Windows آزموده‌شده:
پذیرش‌های MW یا R پاس‌شده و شاهد:
آزمون‌ها: Pass / Fail / Not Run، همراه دلیل:
artifact محلی build و نتیجه نصب:
مصرف/زمان اندازه‌گیری‌شده، اگر موجود:
محدودیت یا blocker واقعی:
دقیقاً یک اقدام بعدی:
وضعیت Core Release:
وضعیت Resolve Assistant:
```

گزارش عمومی نباید token، نام کامل فیلم خصوصی، source inventory یا مسیر خصوصی ماشین را شامل شود. برای مثال‌ها از شناسه fixture استفاده کن.
