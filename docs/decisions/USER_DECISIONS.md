# تصمیمات جاری و تقدم اسناد

تاریخ بسته تحویل: ۲۹ اکتبر ۲۰۲۶. نام نهایی محصول: **Cutora / کاتورا**. ریپو: [Hamrez95/Cutora](https://github.com/Hamrez95/Cutora).

## اختیار فعلی

در این مأموریت کاربر خواسته تمام مستندات و موکاپ‌ها مرتب به ریپو منتقل شوند، مدیریت فیلم/پوشه/هارد کامل توضیح داده شود و START.md برای اجرای توسعه روی کیس تا نسخه آماده نوشته شود. این مأموریت **خودش اجرای محصول روی سیستم مبدأ نیست**. هنگام دستور شروع از START در کیس، ادامه عادی milestoneها از پیش در پرامپت خواسته شده است؛ توقف عمومی «فقط بررسی» در مأموریت اولیه نباید آن نشست را بی‌دلیل متوقف کند.

این تفویض، اجازه خرید، API پولی، ارسال فایل خصوصی، انتشار محتوا یا حذف خام نیست. تأیید لازم برای عملیات حساس، مربوط به همان عملیات و مجموعه فایل است؛ تأیید کلی توسعه جای آن را نمی‌گیرد.

## اولویت‌ها به ترتیب

۱. کار راحت و قابل اعتماد با آرشیو، ورود از دوربین/کارت/هارد، دسته‌بندی، نگه‌داری و انتقال رفت‌وبرگشت SSD/HDD.
۲. جلوگیری از گم‌شدن یا اشتباه‌گرفتن نسخه‌ها، صحت کپی و بکاپ واقعی.
۳. رابط بسیار زیبا و حرفه‌ای، فارسی RTL، موشن مناسب، مراحل کم و بازخورد واضح.
۴. زمان توسعه محدود، نصب ساده روی سیستم دیگر و توسعه‌پذیری بدون پیچیدگی غیرضروری.
۵. تدوین اصلی در DaVinci و بررسی آپشن دستیار Codex برای همان برنامه.
۶. هزینه عملیاتی پایین و مسیر محلی مستقل از cloud.

## مبنای اجرای بعدی

| موضوع | مبنا / دامنه اختیار |
|---|---|
| نام | Cutora؛ تصاویر قدیمی با نام HomeVlog Studio سند مفهومی باقی می‌مانند |
| فناوری | Electron/React/TypeScript/Node/SQLite/FFmpeg مبنای پیشنهادی برای شروع؛ در صورت شکست واقعی Spike، تغییر با ADR مستدل ثبت شود |
| تدوین | DaVinci اصلی است؛ NLE اختصاصی ساخته نشود |
| تجربه رسانه | MEDIA_WORKFLOWS مشخصات جدید و مقدم بر P0/P1 قدیمی است؛ workflowهای SSD/HDD بخشی از هسته‌اند |
| USB | بررسی واقعی و حداکثر تلاش برای اتصال مستقیم؛ پایداری اثبات‌نشده با fallback کارت‌خوان و status صریح |
| دسته‌بندی | تاریخ/رویداد/موضوع/منتخب‌ها با اصلاح دستی؛ semantic AI برای کار پایه اجباری نیست |
| جابه‌جایی | default امن کپی/working copy؛ حذف نسخه قدیمی تنها با تأیید روشن همان عملیات و شرایط spec |
| Resolve assistant | option مستقل با capability probe؛ دستی/اسکریپت داخل برنامه fallback؛ Studio خریداری نشود |
| cloud/social | در اجرای اولیه خاموش و غیرمسدودکننده هسته؛ فعال‌سازی و انتشار نیازمند درخواست مشخص |
| سخت‌افزار | مشخصات PC در طرح فقط انتظار است؛ هر نشست باید واقعیت همان سیستم را اندازه بگیرد |
| ادامه | پس از دستور START، از Spike موفق به هسته ادامه بده؛ برای هر اصلاح کم‌ریسک دوباره اجازه نخواه |

## تقدم در تعارض‌ها

دستور تازه انسان → این سند و START → MEDIA_WORKFLOWS و PLAN/STATUS جاری → گزارش‌های طراحی اولیه → مأموریت اولیه تاریخی.

این ترتیب فقط تعارض زمانی و دامنه کار را حل می‌کند؛ تعهدهای ایمنی خام/حریم خصوصی باقی‌اند. نیاز جدید مدیریت هارد نسبت به MVP اولیه گسترده‌تر است و باید در تخمین جدید پس از Spike لحاظ شود. اعداد ۶۰–۱۰۸ ساعت گزارش قبلی برای محدوده کوچک‌تر بود؛ برای دامنه تکمیل‌شده اکنون تعهد زمانی نیست.

## تصمیم‌هایی که نباید بهانه توقف عادی شوند

رنگ دقیق، آیکن، animation timing، اندازه thumbnail و نام internal module را با قضاوت محصولی انتخاب و ثبت کن. نرخ API و نسخه dependency را در زمان استفاده از سند رسمی کنترل کن. نبود هارد/دوربین واقعی می‌تواند Gate سخت‌افزاری را pending کند، اما مانع ساخت و تست fixture مصنوعی و UI هسته نیست.

## تصمیم‌های واقعاً نیازمند انسان

انتخاب مسیر و مجوز نوشتن روی داده واقعی؛ تأیید cleanup اصل؛ خرید Studio یا هر سرویس؛ upload خصوصی؛ انتشار یا اتصال حساب واقعی؛ تغییر معماری بزرگ با اثر جدی بر دامنه/هزینه. فقط کمترین سؤال لازم را بپرس و کارهای مستقل را ادامه بده.
