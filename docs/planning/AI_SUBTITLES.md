# AI، انتخاب سکانس و زیرنویس فارسی

## چه چیزی AI نمی‌خواهد؟

شناسایی دستگاه، کپی، checksum، dedupe بایتی، گروه‌بندی تاریخ، thumbnail، queue، preset نسبت تصویر و تشخیص صحنه با تغییر تصویر همگی بدون LLM قابل انجام‌اند. event واقعی، رتبه‌بندی شات و storyline معنایی به مدل یا تصمیم انسانی نیاز دارند. AI را برای نام‌گذاری پوشه یا وضعیت بکاپ وارد نکنیم.

جدول تصمیم روش تدوین:

| روش | ارزش | محدودیت | هزینه عملیاتی | جایگاه |
|---|---|---|---|---|
| FFmpeg و rule-based | حذف بازه مشخص، انتخاب بر مبنای طول/حرکت/صدا، render تکرارپذیر | موضوع، طنز و روایت را درک نمی‌کند؛ ASMR با silence-removal خراب می‌شود | API صفر، زمان CPU/GPU | پایه پردازش، نه کارگردان |
| مدل محلی ASR/vision | خصوصی، offline، پردازش متن و فریم | دانلود/VRAM/بسته‌بندی، زمان نگهداری | API صفر؛ برق/ذخیره/زمان | ASR محلی اول؛ VLM بزرگ در P0 رد |
| OpenAI API روی متن/فریم منتخب | پیشنهاد caption و plan از داده کم‌حجم | ارسال داده، هزینه، entitlement و hallucination | وابسته مدل/تعداد توکن | اختیاری پس از ارزیابی؛ ویدئوی MP4 را خودکار به هر endpoint نفرستیم |
| Gemini video understanding | امکان تحلیل مستقیم ویدئو و timestamp | upload، نمونه‌برداری فریم، جزئیات حرکت سریع، هزینه و privacy | بر مبنای توکن modality و خروجی | مقایسه محدود با همان نمونه، نه پیش‌فرض کل آرشیو |
| ابزار AI آماده | کمترین ساخت UI و render engine | کیفیت/پلن/زبان و کنترل محدود | پلن سرویس یا license | اول قابلیت‌های Resolve/Subtitle Edit را بسنجیم |
| Hybrid | metadata/ASR محلی و فقط متن/شات منتخب برای مدل؛ اجرا در Resolve | قراردادها و ارزیابی لازم است | قابل سقف‌گذاری | توصیه برای فاز AI |

## قرارداد پیشنهاد تدوین

تحلیل بر اساس Asset ID و source timecode. برای هر سکانس زمان شروع/پایان، دلیل انتخاب، اطمینان و سبک صدا ذخیره شود. مدل به فایل خام یا shell دسترسی مستقیم نگیرد. بازه بیرون duration، فایل ناموجود، زمان منفی، overlap نامجاز و طول نامتناسب رد شوند. محتوای transcript می‌تواند شامل دستور باشد؛ در اینجا داده است و نباید رفتار agent را عوض کند.

برای ۳۰ فایل، ابتدا metadata و transcript و چند frame نماینده تهیه شود؛ تماس API به ازای هر فریم یا هر ثانیه نزنیم. انتخاب اول کاربر یا rating ساده، تعداد کاندیدها را کم کند. hash محتوا + نسخه مدل + پارامترها + prompt version کلید cache باشند. تغییر دستی از خروجی مدل جدا نگه داشته شود.

خروجی‌های ۳۰ثانیه Reel، ۴۵ثانیه ASMR، ۶۰ثانیه روایت و draft بلند چهار هدف متفاوت‌اند؛ فقط عوض‌کردن مدت کافی نیست. ASMR اولویت صدای ممتد و اتصال طبیعی دارد؛ روایت به رابطه علت/نتیجه واقعی نیاز دارد. کاربر hook، لحظه حساس و پایان را تأیید کند. موسیقی و فایل استوک بدون حقوق مشخص اضافه نشود.

EDL/XML خروجی کمکی است، نه فرمت مرجع داخلی. مرجع، EditPlan نسخه‌دار و مستقل است. adapter رسمی OTIO برای FCP7 XML وجود دارد ولی جدول قابلیت آن همه افکت‌ها/سرعت‌ها را پوشش نمی‌دهد؛ OTIO اصلی هم امروز همه adapterها را پیش‌فرض نصب نمی‌کند. [ماتریس adapter](https://github.com/OpenTimelineIO/otio-fcp-adapter)، [راهنمای adapterها](https://github.com/AcademySoftwareFoundation/OpenTimelineIO/blob/main/docs/tutorials/adapters.md). سازگاری واقعی Resolve بدون import و مقایسه فریم آزموده نشده است.

## انتخاب ASR

| گزینه | مزیت | هزینه/ریسک | تصمیم پیشنهادی |
|---|---|---|---|
| whisper.cpp | executable محلی، CPU و backendهای GPU؛ مناسب همراه بدون Python | انتخاب build/مدل و کارکرد Vulkan/CUDA روی دستگاه واقعی | گزینه نخست برای packaging ساده، مشروط به benchmark |
| faster-whisper | Python/CTranslate2، quantization و batch؛ مناسب PC دارای NVIDIA | runtime CUDA/cuDNN و بسته‌بندی worker بزرگ‌تر | رقیب benchmark روی RTX 4060، نه وابستگی اجباری هسته |
| OpenAI STT | نصب مدل محلی لازم ندارد | شبکه، حریم خصوصی و پرداخت؛ format/timestamp هر مدل باید جدا بررسی شود | opt-in fallback |
| Subtitle Edit | رابط اصلاح و موتورهای متعدد آماده | تجربه خارج اپ و setup موتور | راهکار پیش از توسعه editor اختصاصی |

مستندات [whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/master/README.md)، [faster-whisper](https://github.com/SYSTRAN/faster-whisper)، [Subtitle Edit](https://github.com/SubtitleEdit/subtitleedit/blob/main/docs/features/speech-to-text.md).

بنچمارک مخزن faster-whisper برای ۱۳ دقیقه صوت، مدل large-v2 و کارت RTX 3070 Ti 8GB است؛ نمونه int8 آن حدود ۵۹ ثانیه و حدود ۲٫۹GB VRAM گزارش می‌کند. این نتیجه نه فارسی کاربر است و نه RTX 4060؛ به آن سرعت هدف محصول نسبت نمی‌دهیم. نسخه‌های فعلی CTranslate2 به کتابخانه‌های CUDA/cuDNN مشخص وابسته‌اند؛ قبل از بسته‌بندی باید نسخه‌ها pin و license/distribution آن‌ها کنترل شود. انتخاب اولیه برای آزمون، مدل multilingual medium و large-v3/turbo با batch کوچک است؛ مدل `.en` برای فارسی انتخاب نشود.

## benchmark پیشنهادی، هنوز اجرا نشده

روی PC هدف، ۲۰–۳۰ دقیقه نمونه با اجازه کاربر: گفت‌وگوی آرام دو نفر، فارسی محاوره‌ای و نام‌ها، ابزار/موتور، آشپزی و ASMR بدون گفتار. متن مرجع بخشی از نمونه‌ها را انسان بنویسد؛ ground truth از خروجی مدل دیگر ساخته نشود.

ثبت برای هر موتور/مدل: cold start، زمان بارگیری، wall time، real-time factor، peak RAM/VRAM، حجم دانلود/نصب، خطاهای مهم، WER/CER پس از normalization یکسان، و زمان تصحیح انسانی. زمان‌بندی با خطای median و P95 شروع/پایان خطوط نسبت به مرجع سنجیده شود؛ WER خوب تضمین timestamp خوب نیست.

حدود اولیه پیشنهادی برای تأیید: کار محلی سریع‌تر از طول صوت روی PC هدف، عدم OOM هم‌زمان با کار معمول، قابل اصلاح بودن متن با زمانی کمتر از تایپ دستی، صفر جمله ساختگی پذیرفته‌شده در نمونه سکوت/ASMR پس از بازبینی. آستانه عددی کیفیت فارسی باید پس از baseline تثبیت شود. بدون اجرای این آزمون، «بهترین مدل فارسی» اعلام نمی‌کنیم.

اجرای benchmark به نصب/دانلود مدل نیاز دارد و طبق Gate کاربر در این مرحله مجاز نبود؛ روی سیستم فعلی Iris Xe هم جای RTX 4060 گزارش نمی‌شود.

## زیرنویس: مسیر کم‌خطا

`Generate → Review Text & Timing → Choose Style → Apply in Resolve → Export QC`

سریع‌ترین مسیر: پس از lock شدن draft، ASR روی صدای همان draft اجرا شود؛ در نتیجه نیازی به remap پیچیده همه transcriptهای خام در MVP نیست. transcript خام برای جست‌وجوی کتابخانه در فاز بعد می‌آید. اگر تدوین عوض شد، زیرنویس مشتق باید stale شود و دوباره ساخته یا با mapping معتبر اصلاح شود.

SRT UTF-8 فقط متن/زمان را قابل حمل می‌کند؛ styling و فونت در آن استاندارد جامع و یکسانی بین playerها ندارند. برای burn-in کنترل‌شده، ASS/libass یا قالب تست‌شده Resolve استفاده شود. فیلتر رسمی FFmpeg برای burn-in از libass استفاده می‌کند؛ [منبع کد](https://ffmpeg.org/doxygen/trunk/vf__subtitles_8c_source.html). build باید shaping فارسی و font fallback مناسب داشته باشد؛ فونت پیشنهادی آزاد با فایل license همراه، مثل Vazirmatn.

متن را دستی reverse نکنید. فارسی/انگلیسی، اعداد، نیم‌فاصله، URL، دو خط بلند، emoji و نبود glyph آزمون شود. safe zone برای هر نسبت قابل تنظیم و در preview قابل مشاهده باشد؛ یک حاشیه ثابت برای همه نسخه‌های رابط Instagram/YouTube حقیقت دائمی نیست. karaoke، tracking کلمه و motion عنوان خارج subtitle ساده P0 هستند؛ در Resolve option جدا و edition-dependent بررسی می‌شوند.

## هزینه و حریم خصوصی AI

پیش‌فرض P0: API صفر دلار. محلی رایگان از نظر API است، نه برق، دانلود و زمان GPU. هیچ حساب یا سرویس پولی در این بررسی فعال نشده است.

قیمت دیده‌شده در [مستندات رسمی OpenAI](https://developers.openai.com/api/docs/pricing): mini-transcribe حدود ۰٫۰۰۳ دلار/دقیقه، gpt-transcribe حدود ۰٫۰۰۴۵ دلار/دقیقه، 4o-transcribe حدود ۰٫۰۰۶ دلار/دقیقه؛ یعنی به‌ترتیب حدود ۰٫۱۸، ۰٫۲۷ و ۰٫۳۶ دلار برای ۶۰ دقیقه، بدون retry و هزینه شبکه. کیفیت و timestamp فرمت خروجی بین مدل‌ها یکسان فرض نشود.

برای Gemini، قابلیت دریافت ویدئو در [راهنمای رسمی](https://ai.google.dev/gemini-api/docs/video-understanding) تأیید شده است؛ sampling و حالت پردازش روی کیفیت حرکت سریع و مصرف اثر دارند. در [تعرفه رسمی](https://ai.google.dev/gemini-api/docs/pricing) نمونه Gemini 3.5 Flash-Lite ورودی ۰٫۳۰ و خروجی ۲٫۵۰ دلار/میلیون توکن دارد. مثال صرفاً محاسباتی برای ۳۶۰هزار توکن ورودی و ۱۰هزار خروجی: حدود ۰٫۱۳۳ دلار. این تعداد توکن معادل قطعی هر ساعت ویدئوی کاربر نیست؛ token count واقعی و retry باید اندازه‌گیری شود. مدل ارزان‌تر الزاماً انتخاب سکانس بهتری ندارد.

ارسال فقط با opt-in روشن برای همان پروژه و نوع داده؛ raw خانوادگی و موقعیت منزل پیش‌فرض لوکال. free tier را private مفروض نگیریم؛ سیاست استفاده از داده و دسترسی کشور/حساب از اسناد ارائه‌دهنده در زمان فعال‌سازی کنترل شود. فایل خام، transcript و thumbnail همگی می‌توانند اطلاعات خصوصی داشته باشند. دانلود مدل و استفاده local بعدی با تماس cloud برای inference فرق دارد.

برای استفاده از داخل ایران، دسترسی مستقیم را پیش‌فرض نگیریم: ایران در فهرست فعلی مناطق پشتیبانی‌شده [OpenAI API](https://developers.openai.com/api/docs/supported-countries) و [Gemini API](https://ai.google.dev/gemini-api/docs/available-regions) دیده نمی‌شود. این بررسی، کشور واقعی استفاده یا entitlement حساب کاربر را از timezone نتیجه نمی‌گیرد. قیمت‌های بالا فقط برای دسترسی مجاز و قابل استفاده معنا دارند؛ داشتن یک نشست Codex، دسترسی API این دو سرویس برای محصول را ثابت نمی‌کند. این محدودیت دلیل دیگری برای مستقل‌ماندن مسیر اصلی از cloud است.
