# نقشه راه، برآورد و کنترل هزینه

## اصل برآورد

این برآورد پایین‌به‌بالای فعالیت‌هاست، با اطمینان کم تا متوسط و بدون benchmark ساخت قبلی. فرض: یک توسعه‌دهنده، تجربه پایه قابل قبول با وب/TypeScript، دسترسی به Windows هدف و پذیرش تدوین خارجی در DaVinci. تعداد ساعت آزاد هفتگی هنوز اعلام نشده است؛ «زمان محدود» به معنی ۴۰ ساعت در هفته فرض نمی‌شود.

زمان توسعه، زمان کار Codex و زمان unattended پردازش رسانه یکسان نیستند. اعداد زیر ساعت فعال مهندسی شامل اصلاح و آزمون معمول‌اند؛ خرید سخت‌افزار، یادگیری تدوین DaVinci و انتظار دریافت مجوز حساب جداست.

فازهای ۵ تا ۸ در جمع MVP نیستند. زمان نصب و آزمون اولیه Resolve در فاز۳ لحاظ است؛ یادگیری هنری کاربر یا کد کنترل agent در آن نیست. اگر subtitle خودکار/agent شرط P0 شود، این جمع دیگر معتبر نیست.

جمع فازهای ۰ تا ۴: **۶۰–۱۰۸ ساعت**؛ با ذخیره ریسک پیشنهادی ۲۰٪، حدود **۷۲–۱۳۰ ساعت**. در ۱۰ ساعت کار هفتگی حدود ۷–۱۳ هفته و در ۲۵ ساعت حدود ۳–۵ هفته می‌شود. در نتیجه برای وقت بسیار کم، وعده «اپ کامل در دو هفته» قابل دفاع نیست. راه کم‌هزینه‌تر این است که اکنون با ابزار آماده کار کنیم و اولین سرمایه‌گذاری را به Spike محدود کنیم؛ در صورت شکست ارزش، ساخت را متوقف کنیم.

اگر ویژگی اصلی موردعلاقه «Codex داخل DaVinci» است، پس از تأیید، R0/R1 با سقف ۸–۱۶ ساعت پیش از کتابخانه اختصاصی اجرا شود؛ این زمان بخشی از فاز۶ است و دوباره به جمع آن اضافه نشود. شکست این Spike باید بتواند کل اولویت محصول را عوض کند.

## کنترل scope و توقف

- برای هر Spike سقف زمانی و شاهد عبور نوشته شود؛ پس از رسیدن به سقف، یافته و تصمیم ارائه شود، نه گسترش خاموش کار.
- اگر importer کارت‌خوان در بودجه فاز۲ پایدار نشد، UI/AI تازه اضافه نکنیم.
- اگر سه جلسه baseline نشان داد ابزارهای آماده کافی‌اند، ساخت app متوقف و فقط runbook/قالب‌های تدوین نگه‌داری شود.
- اگر دستیار برای اصلاح خروجی خود بیش از تدوین دستی وقت می‌گیرد، automatic full edit از roadmap حذف و فقط عملیات قطعی حفظ شود.

## توکن: عدد قابل دفاع کجا به دست می‌آید؟

مصرف قبلی Notion، ۶۰۰هزار تا ۳٫۳میلیون، اندازه‌گیری‌شده نیست و در این برآورد استفاده نشده است. برای پروژه‌ای بدون کد، مدل/تنظیمات مشخص، task history و نسبت retry، بازه عددی مستقل برای هر فاز قابل دفاع نداریم؛ درج عدد ظاهراً دقیق در اینجا عددسازی خواهد بود.

روش اجرایی پس از اجازه: فاز۱ را به ۳–۵ task کوچک تقسیم و برای هرکدام input/cached/output، زمان فعال، تعداد دور اصلاح، هزینه و نتیجه Gate را ثبت کنید. یک task انتقال، یکی IPC/SQLite و یکی installer از نظر توکن نماینده یکدیگر نیستند. برای فاز بعد، برای هر دسته مشابه از کمینه/بیشینه مشاهده‌شده استفاده شود:

`برآورد فاز = مجموع تعداد taskهای هم‌نوع × بازه مصرف مشاهده‌شده + ذخیره بازکاری همان دسته`

در جدول بالا همه فازها تا آن نقطه «توکن کالیبره‌نشده» دارند. برای کنترل بودجه، کاربر سقف زمانی/دلاری session تعیین کند و بعد از اولین task نماینده درباره ادامه تصمیم بگیرد. quota اشتراک Codex با invoice API یکی نیست؛ نرخ مدل بدون انتخاب و entitlement مشخص به دلار تبدیل نشود.

## کاهش مصرف توسعه

یک معماری و یک toolchain، قرارداد TS مشترک، یک کتابخانه UI و چند الگوی موشن ثابت. به جای خواندن کل repo در هر task، README و ADR مرتبط و فایل‌های همان تغییر. هر PR/task یک رفتار واقعی با acceptance مشخص داشته باشد. گزارش خطا کوتاه و ساخت‌یافته؛ خروجی log و فایل JSON عظیم در prompt تکرار نشود.

test fixture کوچک و ثابت برای تکرار، یک بسته رسانه بزرگ‌تر برای Gate عملکرد. unit test برای state machine، crash و داده ارزشمند است؛ تستی که فقط JSX یا مقدار ثابت را تکرار می‌کند هزینه اضافی است. snapshot انیمیشن گسترده و بازطراحی سلیقه‌ای در هر دور ممنوع نیست، ولی برای این محدودیت زمان توجیه ندارد.

بازیابی از شکست، نصب‌کننده و codec زود آزمون شوند تا صدها ساعت UI بر زیرساخت نامعتبر ساخته نشود. مدل و فایل خام را وارد repo/context نکنید. ASR/AI روی خروجی lock‌شده یا انتخاب‌های محدود اجرا و نتیجه cache شود. ساخت timeline editor و scheduler بزرگ‌ترین مصرف‌های قابل حذف‌اند.

## هزینه عملیاتی و TCO

| سبد | برنامه پیشنهادی | بازه قابل بیان / عدم قطعیت |
|---|---|---|
| MVP محلی | بدون API و cloud | اشتراک سرویس اجباری صفر دلار؛ برق، اینترنت دریافت ابزار و دیسک جدا |
| ابزار تدوین | DaVinci Free ابتدا | license Studio فقط پس از Gate؛ قیمت خرید در آن زمان تأیید شود |
| ASR ابری اختیاری | فقط نمونه/فایل مورد اجازه | حدود ۰٫۱۸–۰٫۳۶ دلار برای یک ساعت در مثال مدل‌های بررسی‌شده؛ AI_SUBTITLES |
| Buffer | Free ابتدا | ارتقا نمونه دو کانال Essentials: ۱۲ دلار ماهانه یا ۱۲۰ دلار سالانه؛ SOCIAL_PUBLISHING |
| Hosting خروجی برای API Buffer | در P0 ندارد | بدون حجم، retention و ترافیک، عدد معتبر نداریم |
| نگهداری همراه ساده | dependency/runtime، bug، نسخه Windows | ذخیره برنامه‌ریزی ۲–۶h در ماه، کم‌اطمینان؛ با agent/social احتمال بیشتر |
| ذخیره | نسخه مستقل اضافه برای خام | به ظرفیت آزاد و bitrate واقعی بستگی دارد؛ خرید/قیمت‌گذاری انجام نشده |

با ارزش ساعت توسعه R، هزینه زمان سال اول MVP حدود `(۶۰–۱۰۸ + ۲۴–۷۲) × R`، پیش از ذخیره ریسک و بدون گزینه‌هاست. این فرمول نشان می‌دهد زمان مهندسی از اختلاف چند دلار API مهم‌تر است. برای نقطه سربه‌سر: `ساعت ساخت ÷ ساعت صرفه‌جویی واقعی ماهانه`. مثلاً ۸۰ ساعت ساخت با ۴ ساعت صرفه‌جویی ماهانه، پیش از نگهداری حدود ۲۰ ماه بازگشت دارد؛ مثال است، ادعای بازده کاربر نیست.

مقایسه مالی پنج‌ساله با نرخ ساعت، الگوی تولید، hardware refresh و میزان نگهداری نامعلوم قابل اتکا نیست؛ بازه دوازده‌ماهه و اندازه‌گیری پس از Spike برای تصمیم فعلی مناسب‌تر است.
