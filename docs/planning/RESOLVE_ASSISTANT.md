# گزینه محصول: Codex به‌عنوان دستیار تدوین داخل DaVinci

درخواست افزوده‌شده کاربر: تدوین اصلی، کات، موشن و زیرنویس در خود DaVinci انجام شود و Codex در صورت امکان کنترل برنامه را بر عهده بگیرد. **این سند فقط امکان‌سنجی و تعریف گزینه است؛ مجوز شروع پیاده‌سازی یا ادیت اکنون صادر نشده است.**

## پاسخ فنی

ساخت دستیار برای مجموعه مشخصی از کارهای تکراری امکان‌پذیر به نظر می‌رسد. تبدیل آن به «تدوینگر خودکار برای هر درخواست و هر پروژه، با کیفیت نهایی بدون بازبینی» قابل تضمین نیست. سه مسئله جدا داریم: فهم محتوای خام، تصمیم هنری درباره روایت، و اعمال عملیات در Resolve. موفقیت در کلیک‌کردن یا ایجاد timeline، موفقیت در دو مسئله اول را ثابت نمی‌کند.

محصول مناسب: **HomeVlog انتخاب‌ها و EditPlan را آماده کند؛ Codex/adapter یک draft در Resolve بسازد؛ کاربر بازبینی کند؛ نسخه نهایی در همان Resolve رندر شود.** نتیجه، پروژه قابل اصلاح باشد، نه فقط MP4 غیرقابل ویرایش.

## شواهد و حدود دسترسی

- طبق پاسخ مدیر محصول Blackmagic در انجمن رسمی، در نسخه‌های مورد بحث سال ۲۰۲۴، external scripting از terminal/IDE یا شبکه، Studio بوده و Free به Console و scripts menu محدود بوده است. [پاسخ رسمی](https://forum.blackmagicdesign.com/viewtopic.php?f=21&t=205175)، [تأیید دوم](https://forum.blackmagicdesign.com/viewtopic.php?f=21&t=204977).
- این شاهد تاریخی را قرارداد قطعی Resolve 21 نمی‌دانیم. قابلیت دقیق باید از `Help → Documentation → Developer → Scripting` در نسخه نصب‌شده و آزمون R0 استخراج شود؛ از README غیررسمی یا API قدیمی به‌تنهایی تصمیم نگیریم.
- راهنمای رسمی Resolve 21 قابلیت‌های تازه درباره موشن، متن و timing زیرنویس واردشده را شرح می‌دهد؛ وجود در UI به معنی در دسترس بودن در API، edition رایگان یا کیفیت فارسی تضمین‌شده نیست. [راهنمای رسمی Resolve 21](https://documents.blackmagicdesign.com/SupportNotes/DaVinci_Resolve_21_New_Features_Guide.pdf)
- در این سیستم نصب Resolve در مسیر معمول و پردازش در حال اجرا پیدا نشد؛ نصب سفارشی را نمی‌توان از این نتیجه رد کرد. README محلی، edition و API همان نسخه در اختیار بررسی نبود. هیچ اتصال واقعی به Resolve امتحان نشد.
- کنترل Windows با ابزار Computer Use قابل بررسی است و راهنمای مهارت موجود خوانده شد؛ runtime کنترل UI در این مأموریت فعال یا آزمایش نشد. قابلیت همان نشست Codex به ابزارهای فعال آن نشست بستگی دارد. «Codex CLI» به‌تنهایی قرارداد API برای کنترل همه پنجره‌های Windows نیست.

## چهار روش اتصال

| روش | مناسب برای | محدودیت | اولویت پیشنهادی |
|---|---|---|---|
| API رسمی scripting روی همان دستگاه | import، bin، timeline، کات‌های مشخص، marker و render در حد API واقعی | edition، نسخه و پوشش عملیات؛ نیاز احتمالی به Studio | اول، پس از R0 |
| اسکریپت داخل Console/menu برنامه | مسیر کم‌هزینه برای Free در صورت پشتیبانی نسخه | یک اقدام کاربر برای اجرا؛ همه روش‌ها در Free تضمین نیست | fallback رسمی قابل قبول |
| EditPlan → XML/EDL → import در Resolve | مونتاژ پایه بدون نیاز به کنترل همه UI | افکت/زیرنویس/سرعت و relink ممکن است از بین بروند | fallback تبادل، پس از round-trip |
| Computer Use با تصویر، keyboard و UI | بخشی از کنترل‌های فاقد API، تنظیم یک قالب مشخص | کندتر، مصرف screenshot/token، focus/DPI/modal و تغییر UI | آخرین لایه، اختیاری و تحت نظارت |

UI automation راه دورزدن license یا unlock قابلیت Studio نیست؛ فقط عملیات مجاز در edition نصب‌شده را اجرا می‌کند. راهکار رسمی را بر کلیک مختصات ثابت مقدم بدانیم. از خرید Studio پیش از اثبات ارزش adapter خودداری شود؛ قیمت جاری و مسیر خرید در زمان تصمیم جدا تأیید شود.

## تفکیک قابلیت‌ها

سطوح زیر امکان طراحی‌اند، نه پوشش API تأییدشده:

| درخواست | خروجی محدود قابل تعریف | نیاز انسانی / Gate |
|---|---|---|
| «این کلیپ‌ها را وارد کن» | bin و رسانه با مسیر آرشیو ثابت | تطابق تعداد و media online |
| «از این ۵ کلیپ ۳۰ ثانیه بساز» | timeline تازه با source in/out معتبر | بررسی انتخاب شات، ریتم، صدا و cut points |
| «این بخش‌ها را کات کن» | plan قطعی با timecode کسر/فریم | تست ۲۹٫۹۷/۵۹٫۹۴، VFR و offset |
| «یک موشن خفن بزن» | انتخاب از ۲–۳ قالب Fusion/Text+ با پارامتر محدود | ابتدا نمونه مرجع و تأیید قالب؛ موشن دلخواه خودکار خارج محدوده اولیه |
| «زیرنویس فارسی اضافه کن» | SRT اصلاح‌شده + track یا قالب تأییدشده | کنترل RTL/فونت/اعداد، رفع جابه‌جایی پس از trim |
| «ASMR بساز» | کات کم، صدای اصلی، حذف سکوت خاموش | گوش‌دادن انسانی؛ معیار گفتارمحور کافی نیست |
| «برای ریلز و یوتیوب خروجی بگیر» | preset و timeline/کادر مستقل | هر نسبت بازبینی؛ render success با وجود فایل/QC تأیید شود |
| «رنگ و نویز را حرفه‌ای اصلاح کن» | فقط preset محافظه‌کارانه و قابل برگشت | خارج خودکارسازی اولیه؛ کار هنری و edition-dependent |

نام روش‌های API تا مطالعه README نصب‌شده به عنوان قرارداد کدنویسی ثبت نمی‌شوند. تست باید import، timeline creation، range append، subtitle import، template application و render را یک‌به‌یک ثابت کند؛ قابل‌استفاده بودن یکی، دیگری را اثبات نمی‌کند.

## طراحی پیشنهادی

۱. کاربر هدف را انتخاب کند: Reel روایی، ASMR یا draft بلند. کلیپ‌ها/رویداد، مدت هدف، موسیقی مجاز و قالب موشن مشخص باشند.

۲. تحلیل محلی metadata/transcript/keyframe؛ plan نسخه‌دار شامل Asset ID، source in/out، ترتیب، crop، subtitle reference و template ID. پاسخ مدل فقط داده ساخت‌یافته است؛ code، expression یا path دلخواه از آن اجرا نشود.

۳. plan اعتبارسنجی و در HomeVlog نمایش داده شود. نمونه درخواست می‌تواند «۳۰ ثانیه از بازسازی، صدای ابزار حفظ شود، یک عنوان کوتاه، پایان با نمای بعد از کار» باشد؛ اطلاعاتی که در رسانه وجود ندارد ساخته نشود.

۴. export نسخه پشتیبان پروژه و ساخت timeline/workspace تازه با شناسه job. پروژه اصلی overwrite نشود. adapter روی نسخه معلوم Resolve و allowlist عملیات اجرا شود؛ remote scripting شبکه‌ای خاموش، دسترسی local کافی است.

۵. برای قسمت فاقد API، session کنترل UI پس از بررسی وضعیت پنجره عمل کند. اگر modal ناشناخته یا وضعیت مبهم بود، توقف و گزارش؛ blind retry و کلیک پی‌درپی ممنوع. انسان می‌تواند مرحله ناقص را انجام دهد.

۶. پس از هر گروه عملیات، نتیجه از API/تصویر و inventory timeline بررسی شود. undo تنها ابزار rollback نیست؛ checkpoint و project export حفظ شود. تغییر timeline پس از تأیید، نیازمند plan revision جدید باشد.

۷. رندر draft، QC صوت/تصویر/مدت/زیرنویس؛ بازبینی کاربر و سپس render نهایی. خروجی Ready به معنی اجازه نشر نیست. هیچ عملیاتی اجازه حذف original ندارد.

## دو مدل اجرای Codex

**حالت نشست شخصی:** کاربر در Codex خودش یک task مشخص را اجرا می‌کند؛ HomeVlog بسته plan و رسانه مجاز می‌دهد. این مسیر کم‌هزینه‌تر برای PoC است. دسترسی Computer Use و شرایط استفاده همان محیط باید موجود باشد؛ خاموش‌شدن PC یا پایان نشست، agent را متوقف می‌کند.

**حالت محصول مستقل:** خود اپ مدل/agent را فراخوانی و ابزار Resolve را ارائه کند. این قابلیت به API، هزینه inference، احراز هویت، مدیریت session و تست ایمنی نیاز دارد. اشتراک شخصی Codex یا chat به معنی مجوز/سهمیه API داخلی اپ نیست. این حالت P2 است؛ در P1 به CLI پنهان و پروتکل undocumented تکیه نکنیم.

اجرای control loop با screenshot برای هزاران حرکت نسبت به یک اسکریپت قطعی، توکن و زمان بیشتری مصرف می‌کند. اول plan ثابت و batch عملیات، سپس فقط UI استثناها. رابط ارتباطی adapter محلی فایل/فرآیند با schema مشخص باشد؛ MCP عمومی یا سرور شبکه فقط با نیاز واقعی بعدی.

## Gateهای R0 تا R3

| Gate | کار مجاز بعد از تأیید جداگانه | معیار عبور |
|---|---|---|
| R0: قابلیت و edition | ثبت version/edition، README و یک اتصال فقط‌خواندنی | روش رسمی اتصال و مجموعه عملیات واقعی مشخص؛ هزینه Studio در صورت نیاز به کاربر اعلام شود |
| R1: مونتاژ قطعی | پنج فایل fixture در پروژه کپی؛ import و timeline حدود ۳۰ثانیه | تعداد/ترتیب/زمان صحیح، rerun بدون تکثیر، original دست‌نخورده |
| R2: متن و موشن | یک SRT فارسی و یک قالب Fusion از پیش تعیین‌شده | RTL صحیح و timing/فونت درست در preview و export؛ نبود API با fallback شفاف |
| R3: دستیار محتوایی | سه ورودی متفاوت؛ plan و اجرا با بازبینی کاربر | کاهش زمان فعال نسبت به دستی؛ بدون تغییر خارج plan؛ گزارش هزینه و نقاط اصلاح |

برآورد اولیه و کم‌اطمینان: R0/R1 در یک Spike محدود ۸–۱۶ ساعت؛ محصول‌کردن adapter قطعی حدود ۲۴–۴۸ ساعت دیگر؛ موشن/زیرنویس و UI fallback حدود ۲۴–۴۸ ساعت دیگر؛ ارزیابی/مقاوم‌سازی agent حدود ۱۶–۳۲ ساعت دیگر. جمع افزایشی ۷۲–۱۴۴ ساعت قبل از حاشیه ریسک، جدا از MVP آرشیو؛ اگر Free مسیر مطلوب را ندهد یا UI پیچیده باشد بازبرآورد لازم است. این عددها برآورد فعالیت‌اند، نه زمان تضمین‌شده.

## توصیه

گزینه را با عنوان **«دستیار تدوین DaVinci؛ پیش‌نویس قابل بازبینی»** نگه داریم. اولین وعده: import، کات/چینش قطعی، یک قالب عنوان، SRT و render draft. موشن آزاد، color grading خودکار عمومی، انتشار خودکار و «تدوین کامل هر پروژه» خارج وعده اولیه باشند. اگر این گزینه اولویت اصلی کاربر است، R0/R1 را قبل از توسعه کتابخانه اختصاصی بزرگ اجرا کنیم؛ فقط پس از تأیید صریح بعدی.
